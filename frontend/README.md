# PeX Frontend Architecture & Integration Guide

**Platform:** PeX (Payment Exception Resolution Framework)  
**Authoritative UI Bundle:** `frontend/dist/index.html`  
**UI Compiler & Generator:** `build_guided_frontend.py`  
**TypeScript Contracts:** `frontend/src/types/index.ts`  

---

## 1. Authoritative Frontend Prototype

The PeX platform utilizes a single, unified client-side Single-Page Application (SPA) architecture:

* **Production Bundle:** `frontend/dist/index.html` (compiled with full React 18, Tailwind CSS, Lucide icons, RTGS Cutoffs Radar, Policy-as-Code Rule Studio, Multi-Hypothesis Disambiguation, and Maker-Checker HITL Governance).
* **Serving Entrypoint:** FastAPI mounts and serves `frontend/dist/index.html` at `http://localhost:8000/` with SPA routing fallback.
* **Build / Compilation Command:**
  ```bash
  python build_guided_frontend.py
  ```

---

## 2. TypeScript Contracts & Type Safety

* `frontend/src/types/index.ts` contains the synchronized TypeScript domain interfaces matching the backend Pydantic models (`backend/app/schemas/`).
* These definitions cover all 41 BIAN exception profiles, 5 market domains (`DATA_QUALITY`, `PROCESSING`, `COMPLIANCE`, `CLIENT_TREASURY`, `SETTLEMENT_RETURNS`), lifecycle stages, decision recommendations, audit records, and RBAC personas.

---

## 3. Disconnected / Historical Workspace Note (MST-030)

* `frontend/src/` represents the development TypeScript interface definitions.
* The authoritative bundled UI for the web prototype is generated by `build_guided_frontend.py` into `frontend/dist/index.html` to guarantee zero-dependency standalone execution across all deployment environments (including Replit, local containers, and preview hosts).
